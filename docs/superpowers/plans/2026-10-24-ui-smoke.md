# BETA-11 isolated unauthenticated UI smoke

## Contract

Add a separate XCUITest target/scheme for simulator Debug only. One explicit
`--pickup-ui-smoke` app argument must select a synthetic, HTTP-denying Supabase
client before any repository is initialized, skip account restoration and all
launch/foreground/deep-link/push cleanup side effects. The mode must not read or
write auth Keychain storage. Normal launch/configuration and Release behavior
remain unchanged; Release and device builds ignore the UI argument.

Reset only `welcomeIntroCompleted` before Welcome is constructed; do not clear
all defaults or accounts. Root exposes a test-only AX marker with mode and actual
Dynamic Type value, only after isolation is selected. UI tests assert it before
actions and explicitly omit PICKUP_UNIT_TESTS so the single argument is proven.
No live sign-in, fixture, provider, authenticated screen or permissions are needed.

First coverage: deterministic intro/relaunch, account route replacement and email
carry, blank sign-in local validation, and largest Dynamic Type Welcome/account
navigation with kept screenshot attachments. Use real screen controls and bounded
waits. Full BETA-11 and physical acceptance stay open.

## Local gate command

Use a Debug simulator destination; this established lane has Accessibility enabled.
The UI target supports only iphonesimulator and rejects unsupported build conditions
before XCUIApplication is created. Do not point it at a physical phone.
The explicit empty build settings also prove launch without backend credentials:

```sh
xcodebuild test -project ios/PickUpUCF.xcodeproj -scheme PickUpUCFUISmoke \
  -destination 'platform=iOS Simulator,id=2680E61B-4AAF-4A52-9B42-5C5C36777DC1' \
  -parallel-testing-enabled NO SUPABASE_URL= SUPABASE_ANON_KEY=
```

The runner removes PICKUP_UNIT_TESTS from the app launch environment. Each launch
checks the debug-only `ui-smoke-isolated` AX marker first; largest type additionally
asserts its actual SwiftUI value is `accessibility5`. The system launch preference
selects Accessibility XXXL, rather than replacing the product view with a fixture.
Screenshot attachments are retained in xcresult. Account forms and validators are
the actual application UI; no authenticated fake session is introduced.

rendered-UI AX lookup failures recorded during diagnostics work. Read-only
comparison now found the established simulator's ApplicationAccessibilityEnabled
was 0 and AccessibilityEnabled false, versus the earlier recorded 1/true. No app
or test assertion was changed for these failures. This observed post-UI state
must be checked before running the unit tests that traverse UIKit's AX tree.

Restore the simulator-only prerequisite while booted, then restart it so new
processes see the settings. These are environment commands, not product fixes:

```sh
xcrun simctl boot 2680E61B-4AAF-4A52-9B42-5C5C36777DC1 # if shutdown
xcrun simctl bootstatus 2680E61B-4AAF-4A52-9B42-5C5C36777DC1 -b
xcrun simctl spawn 2680E61B-4AAF-4A52-9B42-5C5C36777DC1 defaults write com.apple.Accessibility ApplicationAccessibilityEnabled -int 1
```
